# Celestius Event Registration API

A simple, documented backend for managing registrations for the **Backend Development Workshop**.

| Event | Date | Capacity |
| --- | --- | --- |
| Backend Development Workshop | 20 October 2026 | 50 participants |

## What it does

- Registers students with their name, email, optional college/department, and an automatic registration time.
- Stores data persistently in a local SQLite database.
- Prevents an email address from registering twice (case-insensitively).
- Rejects registrations after 50 seats are taken.
- Lists all registrations and finds a registration by ID.
- Provides interactive documentation and a small automated test suite.

## Technology choices

- **FastAPI** makes it quick to create well-documented JSON APIs and validates incoming data.
- **SQLite** is a real relational database stored in one file. It needs no account or separate server, making it ideal for this small task.
- **Python's built-in `sqlite3`** keeps the database layer transparent and easy to explain.

## Run it locally (Windows PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
uvicorn main:app --reload
```

If PowerShell blocks activation, run this once in the same terminal session, then retry:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Open **http://127.0.0.1:8000/docs** to use FastAPI's interactive Swagger UI. The API is available at **http://127.0.0.1:8000**.

## Endpoints

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/` | Welcome message and documentation link |
| `GET` | `/health` | Check that the server is running |
| `GET` | `/event` | Event information and live seat availability |
| `POST` | `/register` | Register one student |
| `GET` | `/registrations` | List every registration |
| `GET` | `/registrations/{id}` | Get one registration |

### Register a student

**Request**

```json
{
  "name": "Aisha Khan",
  "email": "aisha@example.com",
  "college_department": "Computer Science"
}
```

`college_department` may be omitted.

**Success — `201 Created`**

```json
{
  "message": "Registration successful.",
  "registration": {
    "id": 1,
    "name": "Aisha Khan",
    "email": "aisha@example.com",
    "college_department": "Computer Science",
    "registered_at": "2026-10-24T10:15:30.000000+00:00"
  },
  "event": {
    "name": "Backend Development Workshop",
    "date": "20 October 2026",
    "capacity": 50,
    "registered_count": 1,
    "remaining_seats": 49
  }
}
```

### Expected errors

| Situation | Status | Example response |
| --- | --- | --- |
| Missing or invalid input | `422 Unprocessable Entity` | FastAPI returns a clear field-validation error |
| Email already registered | `409 Conflict` | `{"detail": "A registration already exists for this email address."}` |
| 50 seats are filled | `409 Conflict` | `{"detail": "Event is full. All 50 seats have been filled."}` |
| Registration ID does not exist | `404 Not Found` | `{"detail": "Registration not found."}` |

## Test the API

With the virtual environment activated:

```powershell
pytest
```

The tests check successful registration, lookup by ID, duplicate email rejection, missing ID handling, and the 50-seat capacity rule.

## Implementation notes you can explain in an interview

1. The email column is `UNIQUE` and uses `COLLATE NOCASE`, so `aisha@example.com` and `AISHA@EXAMPLE.COM` count as the same registration.
2. The server normalizes email addresses to lowercase before saving them.
3. Registration time is generated by the server in UTC, so clients cannot fake it.
4. The capacity check and database insert run in one SQLite transaction (`BEGIN IMMEDIATE`). This protects the last available seat if two people register at almost the same time.
5. SQL queries use `?` placeholders rather than building strings from user input, which prevents SQL injection.

## Reset local demo data

Stop the server and delete `event_registrations.db`. It will be created again automatically on the next start. The database file is ignored by Git so sample registrations are not accidentally submitted.
